Set up your Mac to build PWAs

Seven steps, done once. Follow the dark boxes in order; open the grey ones only if you're curious or stuck.

How to run a command

  1. Click Copy on a dark box.
  2. In Terminal, paste on the last line (after the %): ⌘ V
  3. Press Enter and wait until the % comes back.

Accounts to create first

Do these in a web browser, in this order, before step 1.

  • GoogleA new account just for projects, not a personal, school or work one. Turn on 2-Step Verification. Use it to sign up for the others.Recommended
  • GitHubStores your code online. At github.com, sign up with your project Google account.Required
  • VercelPublishes your PWA. At vercel.com, choose Continue with GitHub.Required
  • ClaudeYour AI assistant. At claude.ai, sign in with your project Google account. Claude Code needs a paid plan (Pro or higher).Required
Why?

Google isn't strictly needed, but one account for everything means one password and no “which email did I use?” later. Many simple PWAs also store their data in Google Sheets or Drive.

Avoid school or work accounts: they often block sign-ins to other services and disappear when you leave.

Ages: Google and GitHub require 13+, Claude requires 18+.

1

Developer basicsOpen Terminal and install Apple's tools

  1. Open Terminal: press ⌘ Space, type Terminal, press Enter.
  2. Run this, then click Install in the window that appears: 
    xcode-select --install
Why?

macOS doesn't come with developer tools. This Apple package adds compilers (which build programs on your Mac) and git. The next step, Homebrew, won't install without it.

Terminal is where you type commands. Most developer tools have no app window, so this is where you use them.

Screen looks different?

If it says command line tools are already installed, great: skip to step 2.

2

HomebrewThe tool that installs all the other tools

  1. Run this. It asks for your Mac password (you won't see it as you type; that's normal) and takes a few minutes. 
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
  2. When it finishes, run these two, one at a time: 
    echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
    eval "$(/opt/homebrew/bin/brew shellenv)"
  3. Check it worked: 
    brew --version

    A version number means you're done.

Why?

Homebrew is like an App Store for developer tools: brew install to add, brew upgrade to update everything, brew uninstall to remove.

The two extra lines: Terminal only finds commands in folders on a list called PATH. Homebrew puts its tools in a new folder, /opt/homebrew/bin, that isn't on the list yet.

First line
Saves the setting in a hidden file Terminal reads every time it opens, so it's permanent.
Second line
Applies it to the window that's already open.

Commands that work usually print nothing. That's normal.

Screen looks different?
  • At the end the installer prints “Next steps” with the same two lines, but with your username instead of ~. Both versions do the same thing; use either one.
  • Newer versions may show a third line (echo >> …/.zprofile). It just adds a blank line and is harmless.
  • Older Intel Mac: you may see no “Next steps” at all. Skip the two lines; brew --version will already work.
  • command not found: brew: the two lines weren't run yet, or you're in a different window. Run them again in this window.

Which Mac do you have? Apple menu → About This Mac: “Chip: Apple M…” or “Processor: Intel…”.

3

git, Node and PythonThe working materials

  1. Install all three: 
    brew install git node python
  2. Check them: 
    node -v && git --version && python3 --version

    Three version numbers means you're done.

Why?
git
Saves every version of your project and sends it to GitHub. Vercel publishes from git.
Node
Runs JavaScript tools like Claude Code and Vercel. Comes with npm, which installs JavaScript tools (Homebrew = system tools, npm = JavaScript tools).
Python
Gives you a quick local web server for testing.

Why a server? A PWA doesn't fully work if you just double-click index.html. It needs a web address, and localhost counts. Inside a project folder, python3 -m http.server 8000 makes it available at http://localhost:8000.

Terminal stopped responding?

A running server keeps its Terminal window busy. While it runs, anything you type there is ignored, so commands like git won't run.

  • Free: the last line ends with % and the cursor is waiting.
  • Busy: the last line is server output, like Serving HTTP on… or GET / 200.

To stop the server: click in that window and press Ctrl C. The % comes back.

Better habit: use two tabs. Open a new one with ⌘ T. Tab 1 runs the server; tab 2 is for everything else.

4

Your git identitySign your work

  1. Run both, with your own name and your GitHub email: 
    git config --global user.name "Your Name"
    git config --global user.email "you@example.com"
Why?

Every saved version records who made it, and git won't save until it knows. --global sets it once for the whole computer. Using your GitHub email links your work to your account.

5

GitHub and Claude CodeConnect Terminal to your accounts

  1. Connect Terminal to GitHub, and answer the questions it asks (choose GitHub.com, HTTPS, log in with a web browser): 
    brew install gh
    gh auth login
  2. Install Claude Code: 
    npm install -g @anthropic-ai/claude-code
Why?

GitHub stores your code online. gh auth login signs you in once, so you're never asked for a password again.

Vercel publishes your PWA with HTTPS. Once a project is imported, every change you send to GitHub goes live automatically.

Claude Code is the AI assistant that edits your files. It's installed with npm because it's a Node program, which is why Node came first. -g means you can use it from any folder. You can also use the Claude desktop app instead.

6

A code editorSee and edit your files

  1. Install VS Code: 
    brew install --cask visual-studio-code
Why?

Claude writes most of the code, but you still need to read what changed and make small edits. --cask is Homebrew's way of installing normal apps with a window.

7

A home for your projectsOne folder for everything

  1. Create it: 
    mkdir -p ~/Documents/my-projects
Rules to keep it tidy
  • One project = one folder = one GitHub repo = one Vercel site.
  • No spaces or accents in names: my-app, not My App. Terminal handles spaces badly.

How it fits together

Apple tools→Homebrew→git · Node · Python→npm→Claude Code→GitHub→Vercel (live)

Seven steps, done once. Follow the dark boxes in order; open the grey ones only if you're curious or stuck.

1

TerminalOpen it and allow installed tools to run

  1. Open Terminal: press the Windows key, type Terminal, press Enter.
  2. Run this once: 
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
Why?

Terminal is where you type commands; inside it you use PowerShell. Most developer tools have no app window, so this is where you use them.

By default PowerShell blocks scripts, which also blocks tools like Claude Code. This allows scripts you installed yourself, for your user only.

Screen looks different?
  • Windows 10: if Terminal isn't found, install Windows Terminal from the Microsoft Store.
  • The tab may say Command Prompt instead of PowerShell. Pick PowerShell from the ⌄ menu next to the tabs.
  • If it asks Do you want to change the execution policy?, type Y and press Enter.
2

wingetThe tool that installs all the other tools

  1. Check it's there. It comes with Windows: 
    winget --version

    A version number means you're done.

Why?

winget is Microsoft's App Store for developer tools: winget install to add, winget upgrade --all to update everything, winget uninstall to remove.

About PATH: Terminal only finds commands in folders on a list called PATH. On Windows, installers add themselves to that list, so there's nothing to copy. But Terminal only reads the list when it opens. That's why you open a new one after each install.

Screen looks different?
  • winget is not recognized: common on Windows 10. Update App Installer from the Microsoft Store, then open a new Terminal.
  • The “not recognized” message is worded differently in PowerShell and Command Prompt. Both mean the same: open a new Terminal, or the tool isn't installed yet.

Which Windows do you have? Press Windows + R, type winver, press Enter.

3

git, Node and PythonThe working materials

  1. Install them, one at a time: 
    winget install Git.Git
    winget install OpenJS.NodeJS.LTS
    winget install Python.Python.3.12
  2. Close Terminal, open a new one, and check them: 
    node -v; git --version; py --version

    Three version numbers means you're done.

Why?
git
Saves every version of your project and sends it to GitHub. Vercel publishes from git.
Node
Runs JavaScript tools like Claude Code and Vercel. Comes with npm, which installs JavaScript tools. LTS = the stable version.
Python

Screen looks different?
  • A “Do you want to allow this app to make changes?” box may appear. Click Yes. Some installs don't ask; both are normal.
  • Use py, not python. On many PCs python opens the Microsoft Store instead.
  • Still “not recognized” in a new Terminal? Close all Terminal windows (including inside VS Code), or restart the PC.

Your git identitySign your work

  1. Run all three, with your own name and your GitHub email: 
    git config --global user.name "Your Name"
    git config --global user.email "you@example.com"
    git config --global core.autocrlf true

The third line handles a Windows/Mac difference in how lines of text end, so files stay clean when you work with Mac users.
